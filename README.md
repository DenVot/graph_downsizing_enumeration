# Graph Downsizing Enumeration

Точное решение задачи Graph Downsizing: для каждого заданного размера r найти
индуцированный подграф с максимальной вершинной связностью и сохранить число + свидетель.
Основа — Algorithm 1 статьи Liu et al., *Graph downsizing: a fast heuristic for querying
closely connected subgraphs*, DOI `10.1007/s10732-026-09585-6`.
Внешний перечислитель дерева должен находить все максимальные k-связные подграфы,
а `PDownsize` будет точным перебором.
Актуальное [ТЗ](docs/specification.md) описывает задачу, требования и границы этапов.

**Текущий статус: этап 4 — параллельное точное решение, на ревью.**
Реализованы чтение графов, сетка α/r, Dinic, дерево с перечислителем Wen и sweep,
точный `PDownsize`, поиск оптимума для каждого r и запись общего файла ответов.
`validate`, `tree` и `run` работают. Общий пул распараллеливает перебор текущего уровня.
Checkpoint/resume и GitHub — следующие этапы.
Материалы текущего шага: [этап 4](docs/stage-4-review.md); предыдущего — [этап 3](docs/stage-3-review.md).

## Сборка на Ubuntu 22.04+

```bash
sudo apt-get update
sudo apt-get install -y build-essential cmake nlohmann-json3-dev libboost-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
ctest --test-dir build --output-on-failure
./build/graph_downsizing validate --config examples/config.json
./build/graph_downsizing tree --config examples/config.json
```

Сборка требует C++20, CMake ≥3.22 и nlohmann/json ≥3.10, заголовки Boost и Threads.
Зависимости берутся из установленных пакетов; CMake ничего не скачивает.
Boost.Multiprecision используется для индексов и количества комбинаций.
SQLite, libarchive, OpenSSL и Git будут подключены на последующих этапах.
Для сборки с ASan/UBSan добавьте `-DGRAPH_DOWNSIZING_SANITIZERS=ON` в отдельном build-каталоге.
Исполняемый файл можно установить командой `cmake --install build --prefix /desired/path`.

## Входные графы

Каждая строка ребра содержит ровно два целочисленных идентификатора вершин:

```text
# Комментарий
10 20
20 30
30 10
```

- Идентификаторы — знаковые 64-битные числа; они не обязаны быть последовательными.
- Граф хранится как `std::map<int64_t, std::vector<int64_t>>`: ключи и соседи — исходные
  идентификаторы, без перенумерации.
- Граф неориентированный. Повторные рёбра, включая обратную запись, объединяются.
- Пустые строки и строки, начинающиеся после пробелов с `#` или `%`, пропускаются.
- Петли, лишние столбцы, неверные числа, пустые и несвязные графы отклоняются.
- Вершины определяются по концам рёбер. Изолированную вершину и граф из одной вершины
  этот формат входа не выражает. При этом результат размера r=1 поддерживается.
- Диагностика неверной строки содержит имя файла и номер строки.

Пример `examples/cycle_triangle.txt` — цикл на 6 вершинах и треугольник, соединённые
мостом: 9 вершин, 10 рёбер. Его дерево содержит обе максимальные 2-связные части,
независимо от их разных размеров.

## Потоки и дерево

`VertexFlow` строит сеть для индуцированного подграфа на переданном наборе исходных ID.
Каждая вершина расщепляется на вход и выход; ёмкость внутреннего перехода — 1.
Переходы по рёбрам имеют ёмкость n. Источник — выход первого конца пути, сток — вход
второго, поэтому концы пути не ограничены. Для смежных концов прямой переход имеет
ёмкость 1. Dinic останавливается при достижении заданного k; перед следующей парой
остаточные ёмкости восстанавливаются. Обходы сети итеративные.
В режиме `EdgeCapacity::Unit` все прямые дуги имеют ёмкость 1, как в сети Wen.
При извлечении разреза учитываются и дуги вершин, и дуги исходных рёбер; концы
потока в возвращаемый вершинный разрез не входят.

`is_k_connected` проверяет все неупорядоченные пары до первого неуспеха;
`vertex_connectivity` возвращает точную κ, включая κ=0 для пустого набора и одной вершины.
Локальные индексы вершин используются только внутри потоковой сети.

`MaximalKVCCEnumerator::enumerate(vertices, k)` реализует внешнюю схему KVCC-ENUM:
для каждой части вычисляется k-core, затем выделяются компоненты связности.
Для каждой компоненты вызывается `global_cut`: пустой результат означает k-связность,
непустой — разделитель S размера меньше k. `overlap_partition` возвращает все
компоненты графа без S, добавляя S в каждую; полученные части кладутся в стек `pending`.
Каждая часть снова проходит k-core и выделение компонент. При корректном `GLOBAL_CUT`
результаты максимальны и не повторяются, поэтому отдельного фильтра включений нет.

Класс создаётся с `const Graph&`; исходный граф должен жить дольше перечислителя.
Второй необязательный аргумент — функция-подстановка `GlobalCut`, применяемая в тестах.
По умолчанию вызывается `find_global_cut`: объединяются k лесов scan-first search
(BFS — допустимый порядок), причём рёбра каждого леса удаляются перед следующим.
Сертификат содержит не больше k(n−1) рёбер. В исходном индуцированном подграфе
выбирается вершина минимальной степени. В единичной сети сертификата сначала
проверяются пары «источник — остальные вершины», затем неупорядоченные пары соседей
источника в сертификате. Совпадающие и смежные концы пропускаются.
Поток останавливается при достижении k; найденный меньший разрез возвращается сразу.
`build_tree` использует один перечислитель для всех нод дерева.

`build_tree` начинает с исходного связного графа на уровне 1. Дети ноды уровня k —
максимальные (k+1)-связные части её индуцированного подграфа. Ноды меньше минимального
запрошенного r отбрасываются вместе с дальнейшей веткой. Одинаковые наборы на разных
уровнях разделяют один неизменяемый вектор вершин. Есть индексы уровней для будущего
поиска сверху вниз. κ ноды может быть выше её уровня; уровень задаёт порог проверки.

Текущий вызов CLI для примера:

```bash
./build/graph_downsizing tree --config examples/config.json
```

Команда строит дерево и выводит не больше первых 20 нод и 20 ID на ноду.
Для примера возвращаются корень и две максимальные 2-связные части.
В текущей версии построение последовательное; сохранение и восстановление будут на этапе 5.
Она не выполняет перебор r-подмножеств и не создаёт файлы ответов.
Материалы ревью и проверка полноты: [docs/stage-2-review.md](docs/stage-2-review.md).

## Конфигурация

Полный пример: `examples/config.json`. Для собственного запуска скопируйте его
в `config.local.json` и исправьте пути. Все относительные пути считаются **от каталога
файла конфигурации**, независимо от текущего каталога терминала.

| Поле | По умолчанию | Значение |
| --- | --- | --- |
| `inputs` | обязательное | Непустой список файлов графов, без повторных путей |
| `alpha_step` | `0.1` | Число с плавающей точкой (`double`), 0 < step ≤ 1 |
| `threads` | Число доступных логических процессоров, минимум 1 | Положительное целое |
| `combination_chunk_size` | `256` | Комбинаций в одном диапазоне; положительное целое |
| `working_directory` | `"runs"` | Каталог результатов; состояние появится на этапе 5 |
| `checkpoint_interval_seconds` | `60` | Положительный интервал локального сохранения |
| `github.enabled` | `false` | Включение будущей загрузки |
| `github.repository_url` | не задан | HTTPS URL репозитория GitHub без учётных данных в URL |
| `github.branch` | `"runs"` | Ветка состояния и ответов |
| `github.username` | `"x-access-token"` | Пользователь для GitHub HTTPS |
| `github.token_env` | `"GRAPH_DOWNSIZING_GITHUB_TOKEN"` | Имя переменной окружения с токеном |
| `github.token` | не задан | Альтернатива: токен в локальной конфигурации |
| `github.upload_interval_seconds` | `300` | Положительный интервал будущей загрузки |

Поля `github.token` и `github.token_env` взаимоисключающие. `validate` проверяет их
структуру, но не читает токен из окружения и не проверяет доступ к GitHub.
Неизвестные и повторяющиеся поля конфигурации отклоняются, чтобы опечатки или
перезапись значения не меняли поведение незаметно.
`config.local.json` и `config.*.local.json` исключены из Git; ошибки JSON не выводят
фрагменты исходного файла с учётными данными.

### α и r

Для шага `0.1` создаются α = 0.1, 0.2, …, 1; для шага `0.3` — 0.3, 0.6, 0.9, 1.
Размер `r=max(1,floor(α×|V|))`. Значение α=1 всегда добавляется ровно один раз.
Шаг и α имеют тип `double`; α вычисляется как номер шага × step, без накопления
ошибки последовательного сложения. Размер получается через floor; перед ним
применяется один `nextafter` вверх для обычных границ округления double.
Точная десятичная арифметика не используется.
Сетка генерируется лениво; маленький шаг не создаёт огромный массив задач.
Если число α не помещается в `size_t`, конфигурация отклоняется.
`validate` показывает общее число α и не больше первых 20 размеров на граф.

Несколько α могут давать одинаковый r. Сам результат позже будет вычисляться один раз,
но каждый α получит отдельный блок ответа.
В консоли и файле ответа α записывается с точностью 15 значащих цифр.

## Формат ответа

Для `graph.txt` сохраняется `graph_sol.txt`; граф с индексом i в `inputs` получает
путь `<working_directory>/graph_i/graph_sol.txt`. Индекс предотвращает коллизии,
если у входных файлов из разных каталогов одинаковые имена.

Блоки следуют по возрастанию α, без пустых разделителей:

```text
alpha r k m
u1 v1
...
um vm
```

`r` — число выбранных вершин, `k` — вершинная связность, `m` — точное количество рёбер. Следующие m строк содержат
**все рёбра индуцированного подграфа**, каждое ровно один раз, с исходными идентификаторами.
Порядок вершин и рёбер детерминирован. Для r=1 заголовок имеет вид `alpha 1 0 0`;
идентификатор единственной вершины позже будет сохранён в checkpoint и показан в консоли.

В библиотеке уже есть форматировщик `write_solution_blocks`: он принимает результаты,
проверяет размеры и идентификаторы свидетелей и пишет завершённый префикс сетки α.
Математическую правильность k обеспечивает `ExactSolver`; форматировщик её не вычисляет.
`run` после каждого нового r записывает завершённый префикс через временный файл и
атомарную замену. Повторные r не пересчитываются; каждому α соответствует свой блок.
Оставшийся после аварии `.tmp` требует удаления перед повторным запуском; основной
файл сохраняет предыдущую успешную запись. Это ещё не checkpoint и не восстановление перебора.

## Запуск с пулом потоков

```bash
./build/graph_downsizing run --config examples/config.json
```

Вычисляется один граф и один размер r за раз. Один пул из `threads` работников используется
для всех графов, r и уровней. По умолчанию threads — доступное число логических процессоров.
Внутри текущего уровня диапазоны комбинаций выдаются по очереди нодам по мере освобождения
работников; одна большая нода также использует весь пул. `combination_chunk_size` (по умолчанию 256)
задаёт число комбинаций в диапазоне. Все диапазоны заранее не создаются.
Дерево строится один раз для графа, последовательно; комбинации порождаются последовательно без
материализации всех подмножеств. Поиск идёт от максимального допустимого k к 2,
затем используется связный BFS-префикс. При успехе новые диапазоны не выдаются, работники
завершают начатый поток и проверяют отмену перед следующей парой. Следующий уровень начинается
только после завершения всех работников. Из нескольких оптимальных свидетелей может выбираться
разный набор; k остаётся тем же. Для r=1 выбранный ID выводится в консоль.

Ответ примера: `runs/graph_0/cycle_triangle_sol.txt`. Для r=3 найден треугольник
70,80,90 с k=2; для r=6 — цикл с k=2; для r=9 — весь граф с k=1.

Длительные расчёты пока не защищены восстановлением. `resume` возвращает код 3.
Для `run` требуется `github.enabled=false`: загрузка ещё не реализована.


## CLI и коды завершения

```text
graph_downsizing validate --config FILE
graph_downsizing tree --config FILE
graph_downsizing run --config FILE
graph_downsizing resume --checkpoint FILE --config FILE
graph_downsizing --help
graph_downsizing --version
```

- `0`: успешная проверка входа, построение дерева, решение, помощь или версия.
- `1`: ошибка конфигурации, графа, чтения или записи.
- `2`: неверные аргументы командной строки.
- `3`: запрошенная команда ещё не реализована на текущем этапе.

`validate` только читает данные: не создаёт рабочий каталог, не запускает перебор,
не пишет ответы и не загружает ничего на GitHub.

## Этапы

1. **Каркас — согласован:** сборка, CLI, конфигурация, графы, α/r, формат ответов.
2. **Потоки и дерево — реализованы:** Dinic, полный перечислитель и дерево.
3. Последовательный `PDownsize` и решение всех α — реализованы.
4. **На ревью:** параллельный перебор со строгим порядком уровней.
5. SQLite-checkpoint, восстановление обеих фаз и ZIP.
6. GitHub-загрузка, архивы по частям и эксплуатационные проверки.

Перед этапом 3 добавлена отдельная последовательность Wen: внешняя схема с заглушкой
`GLOBAL_CUT` → ревью → реализация `GLOBAL_CUT` → ревью.
Следующий этап начинается после ревью предыдущего.
Между итерациями выполняется дополнительное ревью тремя независимыми агентами:
алгоритмы, инфраструктура и проверки. Они получают задачу, ТЗ и код без истории чата.
Замечания ревьюеров оцениваются по влиянию на задачу: приоритет — корректность
алгоритма, полнота перебора, потеря результатов и восстановление. Незначительные
замечания показываются пользователю без автоматического исправления.
