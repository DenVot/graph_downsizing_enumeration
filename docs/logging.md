# Логирование

При `run` и `resume` сообщения пишутся в консоль (stderr) и в `run.log` в общем
каталоге checkpoint. При продолжении файл дополняется, прежние записи сохраняются.
Ошибки до открытия лога (например, неверный конфиг или занятой checkpoint) выводятся
только в stderr. Для `validate` и `tree` остаётся прежний консольный вывод.

```json
{
  "input_directory": "graphs",
  "working_directory": "runs/experiment_1",
  "threads": 32,
  "log_interval_seconds": 10,
  "checkpoint_interval_seconds": 60
}
```

`log_interval_seconds` — положительное целое, по умолчанию 10. При resume его можно
изменить. Каждая строка содержит время UTC, уровень INFO/ERROR, PID и время в секундах
от начала текущего процесса. Ресурсы записываются при запуске, периодически и при
штатном завершении. При SIGKILL завершающей строки не будет.

Пример ресурсной строки (числа иллюстративные):

```text
2026-10-11T12:00:10Z INFO pid=1234 elapsed_s=10.00 resources cpu_percent=790.50 rss_mib=512.00 peak_rss_mib=520.00 disk_available_gib=80.20 workers=32 active_tasks=8 queued_tasks=15 finished_tasks=40 graph="network" phase=search alpha=0.1 r=100 k=3 level_nodes_done=4 level_nodes_total=10 level_nodes_percent=40.00 overall_nodes_done=14 overall_nodes_total=50 overall_percent=28.00 search_status=IN_PROGRESS
```

- `cpu_percent` — CPU самого процесса, включая все его потоки, за интервал между
  замерами. 100% = одно полностью занятое ядро, 800% ≈ восемь. Это не процент всей
  машины. В первой записи нет предыдущего замера, поэтому значение `n/a`.
- `rss_mib` — текущая резидентная память процесса, `peak_rss_mib` — её максимум
  с начала процесса. Единица MiB = 1024² байт. Linux: `/proc/self/statm` и getrusage;
  macOS: Mach task_info и getrusage. Недоступные метрики обозначаются `n/a`.
- `disk_available_gib` — доступное место на файловой системе каталога checkpoint.
  Это свободная ёмкость, а не скорость/загрузка диска.
- `workers` — размер пула; `active_tasks` — выполняемые задачи; `queued_tasks` —
  ожидающие; `finished_tasks` — завершившиеся вызовы задач с начала процесса,
  включая раннее завершение по отмене. Это не число доказанных неуспешных нод.
- `graph`, `phase`, `alpha`, `r` — текущий граф, этап, доля и размер подграфа. Построение дерева
  выполняет координатор, поэтому там `active_tasks=0` не означает отсутствие работы.

`level_nodes_percent` — доля завершённых нод текущего уровня `k`; рядом записаны
`level_nodes_done` и `level_nodes_total`. `overall_percent` относится **только к
текущему графу и текущей α/r**: завершённые ноды всех подходящих уровней делятся
на их общее число (`overall_nodes_done` / `overall_nodes_total`). Учитываются уровни
2 ≤ k < r и ноды размера не меньше r. Сохранённые завершённые ноды учитываются при
восстановлении соответствующего уровня.

Когда ответ определён, `search_status=SOLVED`, а `overall_percent=100.00`, в том
числе при раннем успехе, повторном r и r=1. Непосещённые ноды при этом не прибавляются
к `*_nodes_done`. При повторном r ответ берётся из памяти без нового поиска:
счётчики нод равны 0/0, статус SOLVED и общий процент 100%. Одна большая нода может долго оставаться на 0%: это процент нод,
не комбинаций и не оценка оставшегося времени. Вне поиска (например, при построении
дерева) проценты обозначаются `n/a`; для пустого уровня его процент также `n/a`.
Счётчики обновляются при старте уровня и завершении ноды, без блокировок логгера
на каждом подмножестве. Они появляются в периодических ресурсных строках и событиях.

События: старт/продолжение запуска, чтение графа и его размеры, начало/завершение
построения дерева, поиск очередного r, найденный ответ, готовый файл ответа,
завершение или остановка с сохранением checkpoint. Ошибки вычисления после открытия
лога записываются как ERROR. Конфигурация целиком и учётные данные не логируются.

Ресурсы собирает отдельный поток; задания перебора не опрашивают ОС. Запись сообщений
синхронизирована. Каждая строка сбрасывается из буфера C++ на диск, но отдельного fsync
для логов нет: лог не является частью гарантии восстановления checkpoint.
При ошибке фонового логирования выводится диагностика в stderr, монитор завершается;
ошибка записи основного события приводит к сохранению checkpoint и завершению запуска.

Проверки прогресса покрывают переход между уровнями, ранний успех, повторный r,
r=1, восстановленные завершённые ноды и реальные строки лога при остановке/resume.

Для этой итерации прошли все 14 групп CTest на macOS; checkpoint, solver, parallel
и CLI дополнительно прошли под ThreadSanitizer без сообщений о гонках.
