# Этап 2: потоки и дерево

Это материалы исходного этапа 2. Текущее изменение перечислителя
описано в [Wen, шаг 2](wen-step-2-review.md).

## Что изменилось

- `include/graph_downsizing/connectivity.hpp`, `src/connectivity.cpp`: Dinic с расщеплением
  вершин, ограничением потока, сбросом остаточной сети, извлечением разделителя;
  проверка κ ≥ k и точное вычисление κ.
- `include/graph_downsizing/maximal_kvcc_enumerator.hpp`, `src/maximal_kvcc_enumerator.cpp`:
  класс `MaximalKVCCEnumerator` с полным перечислением максимальных по включению
  k-связных индуцированных подграфов через `enumerate(vertices, k)`.
- `include/graph_downsizing/tree.hpp`, `src/tree.cpp`: иерархия Algorithm 1,
  использующая один экземпляр перечислителя для исходного графа.
- `tests/test_algorithms.cpp`: независимый перебор вершинных разрезов, полнота перечисления,
  уровни дерева, связи родителей и детей, отсечение по размеру и разделение памяти.
- CMake и CLI: версия 0.2.0, команда `tree --config FILE`, ещё три группы CTest.

Исходный граф по-прежнему хранится на map с исходными ID. Ноды содержат только наборы
вершин; рёбра берутся из общей структуры. Для потоковой сети вводятся локальные индексы
входов/выходов. Повторяющиеся на разных уровнях наборы имеют общий `shared_ptr`.

## Почему перечисление полное

Вершина степени меньше k не может принадлежать k-связному индуцированному подграфу,
поэтому удаление таких вершин безопасно, в том числе после предыдущих удалений.
Если разделитель S имеет меньше k вершин, k-связный подграф не может содержать вершины
из двух разных компонент графа без S: удаление S разорвало бы его. Значит, искомый
подграф целиком находится в одной из частей C ∪ S. Обработка **всех** таких частей
сохраняет полноту. Найденные k-связные наборы фильтруются по строгому включению.

Разделитель ищется потоками между несмежными парами. Для не полного графа это достаточно
для проверки k-связности; полный граф размера n имеет κ=n−1. Перечислитель оставляет
только наборы размера больше k. Общая проверка `is_k_connected`, предназначенная для
будущего `PDownsize`, проверяет и смежные пары.

Это собственный простой точный перечислитель с интерфейсом внешней процедуры строки 6
Algorithm 1; оптимизации Wen et al. здесь не реализованы. Построение дерева повторяет
строки 1–14 статьи с минимальным r для всей сетки α. Решение по уровням будет на этапе 3.

## Пример для ревью

```bash
./build/graph_downsizing tree --config examples/config.json
```

```text
nodes=3 maximum_k=2
  node=0 parent=0 k=1 size=9 vertices=10,20,30,40,50,60,70,80,90
  node=1 parent=0 k=2 size=6 vertices=10,20,30,40,50,60
  node=2 parent=0 k=2 size=3 vertices=70,80,90
```

Цикл и меньший треугольник сохранены одновременно. В отдельном тесте две клики K4
пересекаются по ребру: перечислитель возвращает обе клики и включает вершины разделителя
в обе части. Исходный набор на уровнях 1 и 2 разделяет один вектор.

## Проверки

- Все **1 099** простых помеченных графов на 1–5 вершинах, включая несвязные:
  точная κ, все пары в обоих направлениях, все пороги потока, корректность разделителей
  и все максимальные k-связные наборы для каждого k.
- **36** случайных графов на 6–8 вершинах с фиксированным seed: те же проверки.
- Деревья для всех **771** связных графов на 2–5 вершинах и связных случайных случаев:
  сравнение каждого уровня с независимым перебором всех подмножеств для каждого
  минимального размера от 1 до n, единственность родителей, включение в родителя,
  полнота индекса уровней и общая память одинаковых наборов.
- Путь из **20 000** вершин: поток между концами без рекурсивного стека.
- Пустой и одноэлементный индуцированные наборы, неверные ID, повторы вершин,
  неверные концы потока и неверные параметры перечислителя/дерева.
- CLI из другого каталога, отсечение превью, запрет checkpoint для `tree`, отсутствие
  записи рабочих файлов; прежние проверки этапа 1 сохранены.

Чтобы проверить несвязные графы без изменения контракта входного TXT, тест добавляет
внешнюю вершину, связанную со всеми остальными, и передаёт в ядро набор без неё.
Оракул работает с битовыми масками, удалениями вершин и достижимостью, без потоков.
Для смежной пары прямое ребро удаляется: оракул находит минимум внутренних удаляемых
вершин между концами и прибавляет один прямой путь.

```bash
podman exec -w /workspace graph-downsizing-stage1-01a0e2b0 cmake -S . -B build-ubuntu-stage2 -DCMAKE_BUILD_TYPE=Release
podman exec -w /workspace graph-downsizing-stage1-01a0e2b0 cmake --build build-ubuntu-stage2 -j2
podman exec -w /workspace graph-downsizing-stage1-01a0e2b0 ctest --test-dir build-ubuntu-stage2 --output-on-failure
podman exec -w /workspace graph-downsizing-stage1-01a0e2b0 ./build-ubuntu-stage2/graph_downsizing tree --config examples/config.json
```

Release-сборки Ubuntu 22.04 / GCC 11.4 и macOS / AppleClang 21 прошли без предупреждений,
**8 из 8** групп CTest прошли. Отдельная Debug-сборка macOS с ASan/UBSan также прошла
все 8 групп без диагностик санитайзеров:

```bash
cmake -S . -B build-stage2-sanitized -DCMAKE_BUILD_TYPE=Debug -DGRAPH_DOWNSIZING_SANITIZERS=ON
cmake --build build-stage2-sanitized -j2
ctest --test-dir build-stage2-sanitized --output-on-failure
```

Перебор r-подмножеств, решение всех α, параллелизм и восстановление ещё не реализованы.
Большие длительные расчёты не запускались; скорость целевого сервера не измерялась.
