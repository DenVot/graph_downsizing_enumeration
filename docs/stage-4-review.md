# Этап 4: параллельный перебор

Версия 0.4.0. Команда `run` использует `threads` и `combination_chunk_size` (по умолчанию 256).
Один `WorkerPool` живёт весь запуск и используется всеми графами и размерами r.

## Выполнение

- Координатор строит дерево один раз и обходит k по убыванию. Все работники текущего уровня
  завершаются до следующего уровня, размера r или графа. Построение дерева остаётся последовательным.
- `CombinationRanges` хранит только курсор каждой ноды, выдаёт непересекающиеся полуинтервалы
  [begin,end) по очереди активным нодам. Работник запрашивает диапазон после завершения предыдущего.
  Предварительной очереди диапазонов нет; активных диапазонов не больше числа работников.
- Число комбинаций и границы — `boost::multiprecision::cpp_int`. `unrank_combination` находит
  начальную комбинацию диапазона; остальные генерируются лексикографическим итератором.
  Даже одна большая нода может обрабатываться всеми потоками.
- У каждого работника своя потоковая сеть для текущего подмножества. Пары проверяются последовательно.
  Первый успех сохраняет свидетель и выставляет флаг отмены. Уже начатый поток завершается,
  затем работник прекращает проверку; новые диапазоны не выдаются.
- Ошибки работников отменяют поиск и передаются координатору после завершения остальных работников.
  Пул можно использовать повторно. Вход в `WorkerPool::run` рассчитан на одного координатора.
- Среди нескольких оптимальных подграфов свидетель зависит от порядка выполнения. Оптимальный k
  и число блоков ответа от числа работников не зависят. Последовательный решатель сохранён для сравнения.

## Проверки

- Все комбинации n<=12 сверены с независимым перечислением битовых масок: число, порядок и завершение.
- C(100,50), ранги за пределами 64 бит и последний ранг; разбиение диапазонов без пропусков/перекрытий.
- Независимый оракул вершинных разрезов: все связные графы до 5 вершин, случайные до 8, все r,
  четыре работника и диапазоны по одной комбинации; оптимум и конкретный свидетель.
- Равные оптимумы при одном и четырёх работниках на примере цикла с треугольником для всех r.
- Полный неуспех одной большой ноды и нескольких нод: счётчики подтверждают полный перебор.
- Успех в клике прекращает выдачу диапазонов; следующий поиск после отмены снова полностью работает.
- Барьер подтверждает одновременное исполнение работников, повторное использование поколений,
  передачу исключений и работу пула после ошибки. CLI проверяет формат, повторные r и файлы нескольких графов.

## Сборка и границы

Добавлены Threads и заголовки Boost (`libboost-dev` на Ubuntu 22.04).
ThreadSanitizer включается отдельной сборкой с `-DGRAPH_DOWNSIZING_THREAD_SANITIZER=ON`;
его нельзя совмещать с `GRAPH_DOWNSIZING_SANITIZERS` (ASan/UBSan).
Проверено: CTest 12/12 на macOS Release (Boost 1.92), Ubuntu 22.04 Release (Boost 1.74)
и macOS ASan/UBSan. ThreadSanitizer: группы solver и parallel, 2/2, без сообщений о гонках.
Три независимых ревью завершены без существенных замечаний.

Checkpoint, сохранение позиции диапазонов, SIGINT/SIGTERM с сохранением, ZIP/resume и GitHub
остаются этапами 5–6. Длительные расчёты не запускались; ускорение на больших графах не измерялось.
Следующий этап начинается после ревью.
