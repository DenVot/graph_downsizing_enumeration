# Параллельный PDownsize и checkpoint

Используется один существующий WorkerPool. Основной поток внутри
`parallel_p_downsize` выдаёт задания и ждёт уведомлений об их завершении.
Задание — диапазон комбинаций одной ноды, а не вся нода. Пары вершин внутри
комбинации проверяются последовательно. Самостоятельный `p_downsize` использует
тот же код поиска синхронно в вызывающем потоке, без создания пула.

## Выдача работы

Комбинации нумеруются от 0 до C(n,r)−1 в лексикографическом порядке.
Для первого подмножества диапазона вычисляем комбинацию по номеру, далее
используем next_combination. Ранги и количество комбинаций имеют тип BigInt.

Координатор держит не более 2 × threads принятых, незавершённых заданий.
Диапазон содержит до 256 комбинаций; для маленькой ноды размер уменьшается до
ceil(C(n,r)/(2 × threads)). Ноды текущего уровня чередуются по кругу.
Восстановленные диапазоны ноды выдаются раньше новых. Изменение числа потоков
не меняет границы уже сохранённых диапазонов.

Завершив задание, работник уменьшает число незавершённых заданий, увеличивает
счётчик завершений и уведомляет condition_variable. Основной поток просыпается
и пополняет окно. WorkerPool сохраняет свою обычную очередь без ограничения;
окно ограничивает только число заданий, которые выдаёт этот поиск.
Новый уровень запускается только после полного неуспеха текущего.

## Состояние ноды

Пример записи внутри progress.json:

```json
{
  "status": "IN_PROGRESS",
  "next_unassigned": "3000",
  "unfinished_ranges": [
    {"begin": "0", "next": "350", "end": "1000"},
    {"begin": "2000", "next": "2300", "end": "3000"}
  ]
}
```

Все номера — десятичные строки произвольной длины. Диапазоны полуоткрытые:
`begin` включается, `end` не включается. `next` — первая непроверенная комбинация.
В этом примере [1000,2000) завершён и больше не хранится. До next_unassigned всё,
что не входит в оставшиеся хвосты [next,end), уже проверено. Начиная с
next_unassigned комбинации ещё не выдавались.

Регистрация нового диапазона и сдвиг next_unassigned публикуются вместе до submit.
Если процесс упал между регистрацией и submit, этот диапазон будет восстановлен.
Работник продвигает next только после полной неуспешной проверки комбинации.
Закончив диапазон, удаляет его из состояния. FINISHED_NOT_FOUND устанавливается,
когда next_unassigned достиг C(n,r) и незавершённых диапазонов больше нет.

Общий mutex поиска используется при выдаче, начале и завершении диапазона и при
найденном ответе. Внутри перебора каждый работник продвигает только свой RangeCursor.
У курсора отдельный mutex для безопасного чтения BigInt при сборе снимка;
общих блокировок на каждую комбинацию нет. Счётчик проверенных комбинаций тоже
локален до завершения задания. Checkpoint::check в обычном пути читает только
атомарные флаги ошибки и сигнала, без общего mutex.

При публикации ноды Checkpoint под своим mutex регистрирует shared_ptr на её курсоры
вместе с JSON состояния. Перед записью он считывает курсоры и обновляет JSON. Граница
выдачи и список диапазонов в это время не меняются. Позиции независимых диапазонов
могут быть прочитаны в разные моменты, но каждая включает только полностью проверенный
префикс: пропусков это не создаёт. Работники продолжают считать во время записи файла;
на границах диапазонов публикация может ждать checkpoint. Формат JSON не изменился.
Запись по-прежнему использует tmp/fsync/rename.
SIGKILL может привести к повтору работы после последнего снимка, но не к пропускам.
При SIGINT/SIGTERM принятые задания выходят на безопасной границе, после чего
сохраняется состояние. Незавершённая проверка комбинации повторяется.

При успехе FINISHED_FOUND и вершины сохраняются немедленно, затем выставляется
отмена всего текущего r. Регистрация курсоров найденной ноды удаляется; поздние
локальные продвижения уже не могут изменить сохранённый ответ.
И при успехе, и при ошибке вызывается pool.wait: состояние поиска и захваченные
ссылки живут до выхода всех принятых заданий. После этого окончательные курсоры
незавершённых нод публикуются, а их регистрации снимаются.

Размер очереди и списка диапазонов зависит от числа работников, а не от C(n,r).
При resume с меньшим числом потоков список может временно содержать больше 2 × threads
диапазонов, оставшихся от прежнего запуска; одновременно выдаётся только текущее
окно. У каждого работника собственная потоковая сеть для текущего подмножества.

## Совместимость

Поддерживается только версия 5 с диапазонами. Старые версии и одиночные курсоры
не преобразуются и не поддерживаются.

## Проверки

Тесты покрывают независимый порядок комбинаций на всех подмножествах до 12 вершин,
ранги больше 64 бит, полное исчерпание диапазонов на циклах, остановку по успеху
на клике и ограничение окна. Отдельно проверяются восстановление двух незавершённых
диапазонов с завершёнными интервалами между ними, независимые курсоры, выделенный,
но ещё не запущенный диапазон, пустая завершённая граница, ошибочные пересекающиеся
диапазоны и отклонение старой версии checkpoint. Процессные тесты проверяют SIGKILL,
SIGTERM/SIGINT и продолжение с другим числом работников.

На macOS и Ubuntu прошли все 14 групп CTest. Checkpoint, solver, parallel и CLI прошли
под ThreadSanitizer без сообщений о гонках. Проверки также включают немедленное
сохранение свидетеля при отмене остальных диапазонов и ошибку записи из работника
с последующим повторным использованием пула.

Проверка локальных курсоров: отдельный тест одновременно продвигает два курсора
и сохраняет JSON, проверяет монотонность и точные конечные позиции, затем снимает
регистрацию и проверяет, что позднее продвижение не меняет сохранённый ответ.

Короткое сравнение 2026-10-11 на macOS: цикл C32, r=16, k=2, 32 работника,
Release без санитайзеров, по два запуска на 6 секунд (порядок: старая, новая,
новая, старая сборка). Старая схема проверила 157–174 тыс. подмножеств/с при
CPU 359–374%; локальные курсоры — 973 тыс.–1,15 млн/с при CPU 881–887%.
CPU взят из периодических логов, объём работы — из checkpoint после SIGTERM.
Это короткий синтетический замер при обычной фоновой нагрузке, не оценка скорости
на пользовательском графе hardware и не гарантия линейного масштабирования.
