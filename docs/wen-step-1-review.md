# Wen, шаг 1: внешняя схема с заглушкой GLOBAL_CUT

Исторические материалы первого шага. Заглушка заменена реализацией в
[шаге 2](wen-step-2-review.md).

Источник: Wen et al., *Enumerating k-Vertex Connected Components in Large Graphs*,
arXiv:1703.08668v1, Algorithm 1, страница 4.

## Что реализовано

`MaximalKVCCEnumerator` следует внешней схеме KVCC-ENUM:

| Строки Algorithm 1 | Реализация |
| --- | --- |
| 2 | `k_core`: удаление вершин степени меньше k до стабилизации |
| 3–4 | `connected_components`: обработка каждой компоненты k-core |
| 5–8 | Вызов `global_cut`; пустой разделитель означает готовый k-VCC |
| 9–11 | Все части `overlap_partition` добавляются в `pending` для повторной обработки |
| 13–18 | Удаление S, компоненты оставшегося графа, возврат S в каждую часть |

Вместо рекурсивных вызовов используется стек `pending`. Каждая новая часть проходит
все шаги заново, включая k-core. Результат сортируется для устойчивого порядка.
Прежние `visited` и фильтр вложенных результатов удалены: при корректных разделителях
размера меньше k максимальность и отсутствие повторов следуют из схемы разбиения.

## Граница текущего шага

Сам GLOBAL_CUT из Algorithm 2 **не реализован**. При обычном вызове его заглушка
бросает `std::logic_error("GLOBAL_CUT is not implemented (Wen step 1)")`.
Наивный перебор пар не используется как скрытая подстановка.

Для проверки схемы конструктор принимает необязательную функцию `GlobalCut`:

```cpp
MaximalKVCCEnumerator enumerator(graph, mocked_global_cut);
auto components = enumerator.enumerate(vertices, k);
```

Подстановка получает исходный граф, отсортированный набор вершин связного
индуцированного k-core и k. Она возвращает разделитель размера меньше k либо пустой
набор, если такого разделителя нет. Неверный непустой разделитель отклоняется;
пустой результат считается утверждением подстановки о k-связности.
`build_tree` принимает ту же необязательную функцию третьим аргументом для тестов.

CLI не подставляет тестовую функцию. Команда `tree` для примера из репозитория
завершается с кодом 1 и диагностикой заглушки. Если все части удалены k-core,
GLOBAL_CUT не вызывается. Команда `validate` продолжает работать.

## Проверки

- Моки с заранее заданными ответами: удаление цепочки при начальном k-core,
  разделение k-core на две компоненты до GLOBAL_CUT, повторное удаление вершин
  после разреза, возврат двух вершин разделителя в три K4, повторное использование
  экземпляра перечислителя.
- Заглушка явно бросает ошибку; неверный разрез не приводит к бесконечному обходу.
- Прежние проверки полноты перечислителя и дерева сохранены. Их GLOBAL_CUT —
  тестовая подстановка на основе полного перебора удаляемых вершин, без потоков.
  Проверяются все графы до 5 вершин, случайные до 8 и отдельные примеры.
- Проверки Dinic сохранены; CLI проверяет диагностику заглушки.

Эти тесты проверяют внешнюю схему при корректной подстановке. Они не подтверждают
реализацию GLOBAL_CUT, разреженного сертификата или оптимизаций sweep.

Release-сборки macOS / AppleClang 21 и Ubuntu 22.04 / GCC 11.4 прошли;
CTest: 9 из 9 групп на обеих системах.
Три независимых ревьюера проверили алгоритм, интеграцию и тесты;
существенных замечаний не нашли.
