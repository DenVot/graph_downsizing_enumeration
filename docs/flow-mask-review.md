# Переиспользование потоковой сети

Для каждого диапазона PDownsize строит один VertexFlow на всех вершинах ноды.
Для каждой комбинации select_indices задаёт маску по позициям в отсортированном
наборе вершин ноды. Топология и память переиспользуются внутри диапазона.
У одновременно исполняемых диапазонов отдельные сети и остаточные ёмкости.

BFS и DFS пропускают дуги к невыбранным вершинам, включая остаточные обратные дуги.
Перед каждой парой сбрасываются ёмкости только дуг между выбранными вершинами,
в обеих половинках расщеплённых вершин. Уровни и указатели DFS сбрасываются только
для выбранных вершин. При реактивации прежде отключённые внутренние дуги также
сбрасываются, поэтому предыдущий поток не переносится на новое подмножество.
Разделитель извлекается только из выбранной части.

Перебор комбинаций и checkpoint-курсоры не изменены. Топология в checkpoint не
сохраняется и при resume строится заново. Память одной активной задачи теперь
зависит от размера всей ноды; списки смежности по-прежнему просматривают рёбра
разреза, но поиск не проходит по ним.

Короткое сравнение на macOS, Release с -O2, один поток: цикл C24, alpha_step=0.5,
полный запуск с файлами ответов и checkpoint. Два запуска до: 6.453 и 6.471 с;
после: 0.718 и 0.771 с. Файлы ответов всех четырёх запусков совпали.
Это синтетический тест, не оценка ускорения на произвольных графах.

Добавлены фиксированные проверки переключения маски на C4: полный цикл, путь,
две несмежные вершины, одно ребро, пустое множество, повторное включение вершин.
Проверяются оба режима ёмкостей, обратное направление потока, разделители,
неактивные концы и некорректные индексы. Процессный тест восстановления использует
C30 вместо C24, чтобы перебор не заканчивался раньше периодического сохранения.

## Ограничение глубины BFS

build_levels завершает обход перед обработкой уровня достигнутого target.
Весь предыдущий уровень обрабатывается, сохраняя все кратчайшие маршруты.
Если target недостижим, BFS остаётся полным для извлечения разделителя.

После изменения прошли все 14 групп CTest. Добавлен фиксированный граф с двумя
короткими маршрутами, третьим более длинным и боковой ветвью; проверены оба
режима ёмкостей, минимальный разделитель и обратное направление потока.
Два независимых ревьюера существенных замечаний не нашли.

Микробенчмарк: один поток, переиспользуемая сеть, 100000 вызовов between с порогом
6, три запуска до/после. На K15,15: 0.322–0.340 с → 0.159–0.180 с;
на K30: 0.463–0.511 с → 0.284–0.317 с. Во всех случаях сумма потоков 600000.
Это измерение потокового ядра на синтетических графах, не полного перебора.

## Сброс только изменённых дуг

Вместо прохода по всем внутренним дугам перед каждой парой используется список
changed_ с индексами дуг изменённых путей. Запись добавляется до изменения ёмкостей;
при сбросе восстанавливается дуга и её остаточная обратная дуга. Ограничение прямого
ребра между концами также учитывается, даже при нулевом лимите потока.
Сброс выполняется перед следующей парой и перед переключением маски, независимо
от активности ранее изменённых вершин. Память списка переиспользуется; повторные
записи допустимы, так как повторный сброс идемпотентен. Объём списка зависит от
суммарной длины увеличивающих путей предыдущего потока.

Все 14 групп CTest прошли; дополнительные фиксированные проверки K4 (нулевой
лимит, раннее завершение, смена концов, отключение и включение вершин) прошли
повторным запуском flow. Два ревьюера существенных замечаний не нашли.

Тот же микробенчмарк 100000 пар, порог 6, три запуска:
K15,15 до 0.167–0.177 с, после 0.124–0.142 с;
K30 до 0.296–0.311 с, после 0.222–0.258 с.
Сумма потоков во всех случаях 600000. Это не измерение полного перебора.

## Отсечение по минимальной степени

PDownsize перед потоками проверяет необходимое условие delta(G[S]) >= k.
Если хотя бы одна выбранная вершина имеет меньше k выбранных соседей, комбинация
считается проверенной и курсор продвигается без вызова between().
Для нод до 64 вершин используются заранее построенные 64-битные маски соседей
и std::popcount; номера исходных вершин переводятся в локальные индексы ноды.
Для более крупных нод просматриваются исходные исходящие дуги к активным соседям
до достижения k. Остаточные ёмкости не влияют на степени.

Проверены размеры нод 4, 64, 65, произвольные исходные идентификаторы, изменение
маски, изменённая остаточная сеть и k=0. Все 14 групп CTest прошли; после добавления
граничных проверок повторно прошли flow, solver, parallel и checkpoint.
Два ревьюера существенных замечаний не нашли. Формат checkpoint не изменён.
