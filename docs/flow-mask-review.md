# Переиспользование потоковой сети

Для каждого диапазона PDownsize строит один VertexFlow на всех вершинах ноды.
Для каждой комбинации select_indices задаёт маску по позициям в отсортированном
наборе вершин ноды. Топология и память переиспользуются внутри диапазона.
У одновременно исполняемых диапазонов отдельные сети и остаточные ёмкости.

BFS и DFS пропускают дуги к невыбранным вершинам, включая остаточные обратные дуги.
Перед каждой парой сбрасываются ёмкости только дуг между выбранными вершинами,
в обеих половинках расщеплённых вершин. Уровни и указатели DFS сбрасываются только
для выбранных вершин. При реактивации прежде отключённые внутренние дуги также
сбрасываются, поэтому предыдущий поток не переносится на новое подмножество.
Разделитель извлекается только из выбранной части.

Перебор комбинаций и checkpoint-курсоры не изменены. Топология в checkpoint не
сохраняется и при resume строится заново. Память одной активной задачи теперь
зависит от размера всей ноды; списки смежности по-прежнему просматривают рёбра
разреза, но поиск не проходит по ним.

Короткое сравнение на macOS, Release с -O2, один поток: цикл C24, alpha_step=0.5,
полный запуск с файлами ответов и checkpoint. Два запуска до: 6.453 и 6.471 с;
после: 0.718 и 0.771 с. Файлы ответов всех четырёх запусков совпали.
Это синтетический тест, не оценка ускорения на произвольных графах.

Добавлены фиксированные проверки переключения маски на C4: полный цикл, путь,
две несмежные вершины, одно ребро, пустое множество, повторное включение вершин.
Проверяются оба режима ёмкостей, обратное направление потока, разделители,
неактивные концы и некорректные индексы. Процессный тест восстановления использует
C30 вместо C24, чтобы перебор не заканчивался раньше периодического сохранения.
