# Этап 3: последовательное точное решение

`run --config FILE` теперь рассчитывает ответы. Версия приложения 0.3.0.

## Алгоритм

`p_downsize` в `src/solver.cpp` лениво перебирает r-комбинации отсортированного набора
вершин. Для каждого индуцированного подграфа `is_k_connected` использует Dinic для
всех неупорядоченных пар до первого неуспеха; прямое ребро учитывается один раз.
Возвращается первый подходящий набор либо отсутствие ответа после полного перебора.

`ExactSolver` строит дерево один раз с минимальным запрошенным r. `solve(r)` идёт по
уровням k от min(r−1, максимальный уровень) до 2 и по всем подходящим нодам уровня.
Первый успех даёт оптимум. Если успеха нет, BFS выбирает связный набор размера r:
k=1 при r>1, k=0 при r=1. Решения кэшируются по r; повторные α не запускают новый поиск.

## Запись и CLI

Графы и α обрабатываются последовательно. После каждого нового r `save_solution_file`
формирует завершённый префикс сетки α в соседнем временном файле, закрывает его и
заменяет основной файл. Формат: `alpha r k m`, затем все m индуцированных рёбер.
Для одноимённых входов предусмотрены отдельные каталоги `graph_0`, `graph_1`, …;
для r=1 выбранный ID показывается в консоли. Повторный run заменяет файлы, не дописывает блоки.

Ошибка записи прекращает расчёт. Коллизии выходного пути с любым входом или другим выходом (включая ссылки
на общий каталог) отклоняются до вычислений. Существующий `.tmp` не перезаписывается: после аварии его нужно удалить.
Проверяется успешное закрытие файла; гарантий сохранения при отключении питания на этом этапе нет.

## Проверки

- Независимый оракул на битовых масках и удалении вершин: все графы до 5 вершин,
  случайные до 8, все допустимые r и k для PDownsize; сравнение первого свидетеля.
- На связных входах: оптимум и конкретный свидетель для каждого r, повторные r,
  дерево с отсечением малых нод, r=1, r=|V|, k>=r и невалидные параметры.
- Цикл плюс треугольник: неуспех в большой ноде не мешает найти меньшую ноду того же уровня;
  отдельно проверены ответы для r=3,4,6,9.
- CLI: два графа с одинаковым именем, повторные r и полный формат ответа, повторный запуск,
  пример из репозитория, ошибка записи и защита исходного графа от перезаписи.
- Запись: невалидный свидетель сохраняет предыдущий файл, временный файл убирается при ошибке,
  успешная запись совпадает с форматировщиком; конфликт с существующим временным файлом диагностируется.

Проверено: CTest 11/11 на macOS Release, Ubuntu 22.04 Release и macOS ASan/UBSan.
Три независимых ревью завершены; найденная коллизия выходных путей исправлена и перепроверена.

## Границы этапа

Один вычислительный поток. Настройка threads будет применяться на этапе 4.
Checkpoint, обработка сигналов с сохранением, resume, ZIP и GitHub остаются этапами 5–6.
`resume` возвращает код 3; `run` требует отключённого GitHub. Длительные вычисления
не запускались. Следующий этап — только после пользовательского ревью.
