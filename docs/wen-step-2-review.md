# Wen, шаг 2: GLOBAL_CUT

Источник: Wen et al., *Enumerating k-Vertex Connected Components in Large Graphs*,
arXiv:1703.08668v1, Algorithm 2 и §4.2, страницы 5–6.

## Реализация

`global_cut.hpp` / `global_cut.cpp` содержат две процедуры:

- `sparse_certificate`: строит до k лесов scan-first search, каждый раз удаляя рёбра
  полученного леса из остаточного графа. Порядок сканирования — BFS; в каждом проходе
  обрабатываются все остаточные компоненты. Объединение лесов содержит те же вершины,
  только исходные рёбра и не больше k(n−1) рёбер. При исчерпании рёбер проходы прекращаются.
- `find_global_cut`: выбирает вершину минимальной степени в исходном индуцированном
  подграфе, строит потоковую сеть сертификата и выполняет две фазы Algorithm 2.
  Первая проверяет источник со всеми вершинами, вторая — неупорядоченные пары его
  соседей в сертификате. Самопары и смежные пары пропускаются, первый разрез размера
  меньше k немедленно возвращается. Пустой результат означает k-связность.

Сертификат принимает связный индуцированный набор минимум из двух вершин и k ≥ 1.
GLOBAL_CUT дополнительно требует k < числа вершин. Ноды после k-core удовлетворяют
этому контракту. ID исходные; внешние вершины и рёбра не попадают в сертификат.

Для LOC-CUT переиспользуется `VertexFlow` с новым режимом `EdgeCapacity::Unit`.
Все прямые дуги имеют ёмкость 1; источник и сток — выход/вход соответствующих концов.
Сеть строится один раз, остаточные ёмкости сбрасываются для каждой пары; поток
останавливается при достижении k.

В единичной сети минимальный разрез может пересекать дуги исходных рёбер.
При восстановлении берётся вершина на конце пересечённой дуги, а если это сток —
вершина в её начале. Повторы объединяются. Каждый пересечённый переход покрыт,
а концы потока не удаляются. Прежний режим ёмкости n также поддерживается.

`MaximalKVCCEnumerator` по умолчанию вызывает реальный GLOBAL_CUT. Подстановки
сохранены для тестов внешней схемы. `tree` снова работает без подстановок.
Реализация использует map/set; оценки линейного времени специализированных структур
из статьи на неё не переносятся. Sweep-оптимизации из §5 пока не реализованы.

## Проверки

- Диниц: оба режима ёмкостей, все пары и пороги на всех графах до 5 вершин,
  случайные графы до 8; сравнение числа путей и вершинных разрезов с удалением вершин.
- Сертификат: состав вершин/рёбер, ограничение k(n−1), сохранение компонент после
  каждого удаления менее k вершин на связных графах из тех же малых наборов.
- GLOBAL_CUT: пустой ответ эквивалентен κ ≥ k; любой непустой ответ проверяется
  как разрез исходного индуцированного графа независимым обходом.
- Пример из двух K5 и двух вершин разделителя: источник входит в разделитель,
  первая фаза не находит разрез, а вторая возвращает обе вершины. В этом примере
  сертификат действительно содержит меньше рёбер, чем исходный граф.
- Полнота перечислителя и дерева проверяется с реальным GLOBAL_CUT; перечислитель
  дополнительно сравнивается с тестовой подстановкой на переборе удалений.
- CLI снова проверяет дерево для цикла плюс треугольник.

Release-сборки macOS / AppleClang 21 и Ubuntu 22.04 / GCC 11.4:
CTest 10 из 10 групп. Debug-сборка macOS с ASan/UBSan: 10 из 10,
без диагностик санитайзеров.
Три независимых ревьюера проверили алгоритм, интеграцию и тесты;
существенных замечаний не нашли.

После проверки этого шага — остановка на пользовательское ревью.
